# 剪贴板链接检测

日期：2026-08-13  
状态：需求已确认，尚未实现

用户从浏览器复制视频链接后切回 MediaBrief，应用在确认后才接入转写。这是桌面窗口上的小功能，不改现有粘贴框、队列和转写链路。

## 目标体验

1. 在 YouTube、B 站等站点复制链接。
2. 切回 MediaBrief。
3. 若链接是本软件能处理的视频站点，弹出确认框。
4. 用户三选一：不再提醒、忽略、开始转写。

手动往输入框粘贴、拖文件、RSS、Bot 送链接，都不走这套检测。

## 已确认的产品决策

1. **每次接入都必须确认。** 没有「以后默认直接开始转写」。剪贴板里出现链接就自动开任务会很怪，第一版不做，后面也不要偷偷加。
2. **弹窗三个按钮，从左到右：不再提醒、忽略、开始转写。**
   - **开始转写**：切到转录页，调用现有 `enqueueUrl`，立刻进队列。不要只填输入框再让人按一次。
   - **忽略**：关掉这次提示。剪贴板下次换成另一条可处理链接时，仍可再问。
   - **不再提醒**：关掉这次提示，并且以后都不再因剪贴板弹出。不开始转写。这是关闭检测的入口，设置页不另做开关。
3. **设置页不出现这项。** 开着检测时靠弹窗问；关掉检测时靠「不再提醒」。第一版不提供从设置里重新打开的入口。
4. **只在桌面窗口做。** `--no-window` 或浏览器打开时不读剪贴板。
5. **只在应用重新成为前台、且剪贴板确实变了时读一次。** 后台不轮询。
6. **启动时剪贴板里已有的旧内容不弹。** 只处理启动之后新复制的。
7. **用站点白名单，不用「任意 URL」。** `GenericAdapter` 对所有地址都匹配，不能当检测条件。

## 三个按钮分别做什么

| 按钮 | 这次 | 以后 |
|------|------|------|
| 不再提醒 | 关弹窗，不开任务 | 不再因剪贴板弹出 |
| 忽略 | 关弹窗，不开任务 | 新链接仍可再问 |
| 开始转写 | 关弹窗，立刻 `enqueueUrl` | 检测仍开着 |

「不再提醒」关掉的是剪贴板询问，不是软件处理链接的能力。用户仍可手动粘贴。

## 什么时候问、什么时候不问

问，当同时满足：

- 桌面窗口在前台（从其他应用切回来，或本机剪贴板在 MediaBrief 已在前台时发生变化）。
- 用户没有点过「不再提醒」。
- `NSPasteboard.changeCount` 相对上次已检查的值变了。
- 剪贴板带 URL 类型（Safari「复制链接」会有 `public.url`），而不是一段纯文本。
- URL 的 host 落在白名单。
- 这条 URL 不是当前输入框里的内容，也不在队列里。
- 用户此刻没有在输入框或其它文本框里打字。

不问：密码、普通网页、纯文本、启动前的旧剪贴板、同一条刚被忽略的链接、检测已被「不再提醒」关掉。

白名单第一版与历史页站点分类对齐，并补上已有平台适配器：

- YouTube：`youtube.com`、`youtu.be`
- Bilibili：`bilibili.com`、`b23.tv`
- 抖音：`douyin.com`、`iesdouyin.com`、`v.douyin.com`
- 以及历史页已有的 Vimeo、Twitch、Niconico、Dailymotion、TikTok、小红书、西瓜视频

这份名单应抽成前后端可共用的一份，不要和 `HistoryPage` 各写一份。不在名单里的地址一律不弹，即便 yt-dlp 其实能下。

本地文件路径、RSS 订阅、一次复制多条链接、预拉视频标题，第一版不做。

## 界面

用现有 `AlertDialog`，不要系统原生 Alert，也不要用 Toast。

- 标题：检测到可转写的链接（文案走 i18n，en/zh/ja/ko 同步）。
- 正文：站点名 + 完整 URL（过长截断，可复制）。
- 按钮区：左侧「不再提醒」（次要/幽灵按钮），右侧「忽略」（描边）和「开始转写」（主按钮）。
- 主按钮默认聚焦。Esc 和点遮罩等同「忽略」，不等于「不再提醒」。

## 技术落点

前端 `navigator.clipboard.readText()` 在 pywebview / WKWebView 里没有用户手势时经常读不到。剪贴板读取放在 Python 原生层。

```text
应用成为前台
  → 若已「不再提醒」，结束
  → 读 changeCount；没变则不碰剪贴板内容
  → 无 URL 类型则结束（避免读到密码等纯文本）
  → 取出 URL，白名单过滤
  → evaluate_js 通知前端
  → 前端弹确认框
  → 开始转写 → enqueueUrl
     忽略 → 记下本条，本次会话不再为它弹
     不再提醒 → 本地记下关闭，之后不再检测
```

macOS 15 会在应用读取剪贴板时显示 “MediaBrief pasted from …”。`changeCount` 没变就不读内容；没有 URL 类型也不读字符串。这样切回应用但并没复制新链接时，不应刷系统粘贴条。

「不再提醒」用 `localStorage` 即可，不进 SQLite、不进设置 API。这是本机 UI 偏好，不是密钥。重装或清站点数据后检测会恢复，第一版可接受。

涉及文件（实现时再改，本文不预写补丁）：

- `start.py`：窗口激活时读剪贴板，把候选 URL 交给前端。
- 前端全局一层（`App.tsx` 或独立 hook）：收事件、弹框、三个按钮。
- `useTranscribe.ts` 的 `enqueueUrl`：确认后复用，不新开一条处理链路。
- `frontend/src/i18n/dictionaries.ts`：四种语言文案。
- 站点白名单：从 `HistoryPage` 的 `PLATFORM_PATTERNS` 抽出来，检测与历史分类共用。

## 明确不做

- 后台常驻监听剪贴板。
- 复制后不确认、直接进队列。
- 设置页里的开关或「恢复剪贴板提示」。
- 浏览器模式、Windows。
- 用 `GenericAdapter` 匹配任意网址。
- 为了弹窗去跑 yt-dlp 取标题。
- 系统通知、菜单栏常驻后再提示。

## 实现顺序

1. 抽出站点白名单，补上抖音短链；给纯函数测试。
2. Python：应用激活 + `changeCount` + URL 类型才读；把候选 URL 发给前端。
3. 前端确认框与三个按钮；「不再提醒」写入 `localStorage`。
4. 「开始转写」接到现有 `enqueueUrl`。
5. 四种语言文案。
6. 桌面窗口手测：白名单链接会问、普通网址不问、启动旧剪贴板不问、Esc 只忽略、不再提醒之后彻底安静。

验收只看桌面窗口。没有窗口的运行方式不测这项。
